# Αξιολόγηση του project και πρόταση σχεδιασμού

*Νοέμβριος 2026*

## Συμπέρασμα

**Αξίζει να συνεχιστεί, αλλά όχι με ξαναγράψιμο από το μηδέν.** Ο βασικός σκελετός είναι σωστός για τον
σκοπό του: καθημερινό pipeline στο GitHub Actions, στατικό site χωρίς server, ιστορικό στο git, και
ζωντανή αξιολόγηση των προβλέψεων. Τα προβλήματα είναι συγκεκριμένα και διορθώνονται σταδιακά. Τα πιο
σημαντικά διορθώθηκαν ήδη (δες «Τι άλλαξε τώρα»).

Το πιο σημαντικό εύρημα: **στο NBA δεν υπάρχει edge απέναντι στην αγορά** με τα δεδομένα που έχουμε (box
scores). Οι γραμμές κλεισίματος είναι πιο ακριβείς από κάθε μοντέλο του project, και ένα μοντέλο που
ποντάρει όπου διαφωνεί με την αγορά χάνει περίπου 5–10%. Αυτό είναι το αναμενόμενο για μια από τις πιο
αποδοτικές αγορές στον κόσμο. Η ρεαλιστική ελπίδα για edge είναι οι μικρότερες λίγκες (GBL, EuroCup),
όπου όμως πρέπει πρώτα να μαζευτούν αποδόσεις για να ελεγχθεί.

## Τι δουλεύει καλά

- **Pipeline:** απλό, ντετερμινιστικό, χωρίς server, με κόστος μηδέν.
- **Πολλαπλές πηγές σε κοινό σχήμα δεδομένων** (EuroLeague API, ESAKE, ESPN, ΕΟΚ). Μια νέα λίγκα θέλει μόνο έναν scraper.
- **Ζωντανή αξιολόγηση με αρχείο προβλέψεων πριν το ματς.** Είναι το σωστό μέτρο, όχι μόνο backtest.
- **Χρονικά splits παντού.** Δεν υπάρχει διαρροή μελλοντικής πληροφορίας στα μοντέλα.

## Αδυναμίες (με σειρά σημασίας)

1. **Τα μοντέλα αγώνων έβλεπαν μόνο την τρέχουσα σεζόν.** Το Monte Carlo και τα νευρωνικά ξεκινούν κάθε
   σεζόν από το μηδέν, οπότε τον Οκτώβριο-Νοέμβριο προβλέπουν σχεδόν στα τυφλά. Τα ratings με χρονική
   απόσβεση που μεταφέρουν πληροφορία από την προηγούμενη σεζόν είναι σαφώς καλύτερα (Brier walk-forward):

   | | Ratings | Monte Carlo |
   |---|---|---|
   | EuroLeague | 0.2145 | 0.2207 |
   | EuroCup | 0.2081 | 0.2142 |
   | GBL | 0.1561 | 0.1739 |
   | NBA | 0.2019 | 0.2073 |

2. **Καμία διόρθωση για τη δυσκολία του προγράμματος.** Τα ORTG/DRTG ήταν ακατέργαστα: μια ομάδα που έπαιξε
   με τους αδύναμους φαινόταν καλύτερη απ' ό,τι είναι.
3. **Σταθερές παράμετροι για όλες τις λίγκες.** Το Monte Carlo έχει έδρα 3 π. και σ = 10 παντού. Στην πράξη
   η έδρα είναι ~1–2 π. στο NBA και ~3–5 π. στη GBL, και η τυπική απόκλιση της διαφοράς είναι ~12 στην Ευρώπη
   και ~14.5 στο NBA. Με σ = 10 το Monte Carlo είναι υπερβολικά σίγουρο (κάλυψη 66% αντί για 80%).
4. **Δεν λαμβάνονταν υπόψη οι απουσίες.** Είναι η μεγαλύτερη πληροφορία που έχει η αγορά και λείπει από τα
   ratings ομάδας. Στο NBA η απουσία ενός σταρ αλλάζει τη διαφορά κατά 5–7 πόντους.
5. **Αναλύσεις χωρίς στατιστικό νόημα.** Οι κατατάξεις ανά αγώνα (όχι ανά κατοχή), τα ποσοστά χωρίς
   διόρθωση δείγματος και το scatter με ελεύθερες μεταβλητές έδειχναν κυρίως ρυθμό, λεπτά και θόρυβο.
6. **Ίδια λογική σε δύο γλώσσες.** Το `MatchSim` (JS) και ο `GameSimulator` (Python) πρέπει να μένουν
   συγχρονισμένα με το χέρι. Ο browser επαναϋπολογίζει ό,τι υπάρχει ήδη στην Python.
7. **Τεχνικά:**
   - το `app.js` είναι ένα αρχείο ~1.600 γραμμών,
   - δεν υπάρχουν tests,
   - τα CSV στο git μεγαλώνουν συνεχώς,
   - το μοντέλο παικτών και τα νευρωνικά αγώνων κοστίζουν ~25 λεπτά CI την ημέρα, για μικρό όφελος.
8. **Το μοντέλο παικτών** (MAE PTS/REB/AST) έχει μικρή αξία για πρόβλεψη αγώνων ή στοίχημα. Είναι ωραίο για
   παρουσίαση, αλλά δεν είναι προτεραιότητα.

## Πώς θα το σχεδίαζα από την αρχή

```
ingest/      scrapers -> ακατέργαστα δεδομένα (ίδιο σχήμα, ένας φάκελος ανά πηγή)
             + αποδόσεις (ESPN, The Odds API, Pinnacle αν υπάρχει πρόσβαση) + τραυματίες
store/       ένα αρχείο DuckDB/Parquet αντί για δεκάδες CSV (ερωτήματα "as-of ημερομηνία" χωρίς διαρροή)
features/    ένας κοινός builder "τι ήξερα στις Χ/Υ": ratings, απουσίες, ξεκούραση, ταξίδι
models/      1) ratings (ridge με απόσβεση, ανά λίγκα)          <- ο πυρήνας
             2) διόρθωση απουσιών (αξία παικτών)
             3) προαιρετικά: NN/GBM πάνω στα παραπάνω (όχι στη θέση τους)
             4) συνδυασμός με την αγορά (blend) για όποιο στοίχημα
eval/        walk-forward για όλα, σύγκριση με την αγορά, CLV, έλεγχοι σημαντικότητας
publish/     JSON έτοιμα για προβολή (ο browser ΔΕΝ ξαναϋπολογίζει μοντέλα)
site/        ES modules (ένα αρχείο ανά σελίδα), ίδια αισθητική
tests/       μικρά tests για scrapers (parsing) και για διαρροή μελλοντικής πληροφορίας
```

Βασικές αρχές:

- **Μία πηγή αλήθειας για τις προβλέψεις, στην Python.** Ο browser μόνο τις δείχνει. Το Monte Carlo στον
  browser μπορεί να μείνει ως διαδραστικό παιχνίδι, με παραμέτρους από την Python.
- **Η αγορά ως baseline.** Κάθε μοντέλο συγκρίνεται με τις αποδόσεις κλεισίματος, όχι μόνο με άλλα μοντέλα.
- **Κάθε αριθμός στο site με μέγεθος δείγματος ή αβεβαιότητα,** και διόρθωση για πολλαπλούς ελέγχους όπου
  ψάχνουμε «ποιος ξεχωρίζει».

## Τι άλλαξε τώρα

- `scripts/ratings.py`: κοινή μηχανή ratings, προσαρμοσμένων στον αντίπαλο, με χρονική απόσβεση, έδρα
  από τα δεδομένα και απουσίες βασικών.
- `scripts/analytics.py` και η νέα σελίδα «Ανάλυση». Περιλαμβάνει:
  - προσαρμοσμένα ratings και δυσκολία προγράμματος,
  - τύχη (νίκες − αναμενόμενες) και κλειστά ματς,
  - ανάλυση four factors σε πόντους,
  - πλεονέκτημα έδρας με διάστημα εμπιστοσύνης,
  - παίκτες ανά 100 κατοχές με usage, TS% με διόρθωση δείγματος, AST/REB/TOV% και on/off με συρρίκνωση,
  - «φόρμα: σήμα ή θόρυβος» με διόρθωση Benjamini–Hochberg. Σχεδόν όλες οι «φόρμες» αποδεικνύονται θόρυβος.
- `scripts/scrapers/odds_espn.py`, `injuries_espn.py`, `odds_api.py`: αποδόσεις και τραυματίες.
- `scripts/edge_model.py` και η νέα σελίδα «Στοίχημα». Περιλαμβάνει:
  - walk-forward ratings με απουσίες και βαθμονόμηση,
  - έλεγχο «πληροφορίας πέρα από την αγορά»,
  - backtest με bootstrap διαστήματα,
  - συστάσεις μόνο όπου το edge αποδεικνύεται,
  - αρχείο προβλέψεων με CLV.

## Επόμενα βήματα (με σειρά αξίας)

1. **Κλειδί The Odds API** (δωρεάν, GitHub secret `ODDS_API_KEY`). Χωρίς αποδόσεις για EuroLeague, EuroCup
   και GBL δεν μπορεί να ελεγχθεί εκεί το edge, που είναι και το πιο πιθανό σημείο να υπάρχει. Μετά από
   ~2–3 μήνες καταγραφής, το CLV θα δείξει αν το μοντέλο «βλέπει» κάτι νωρίτερα από την αγορά.
2. **Γραμμές ανοίγματος.** Το edge, αν υπάρχει, βρίσκεται στις πρώιμες γραμμές, όχι στο κλείσιμο. Χρειάζονται
   στιγμιότυπα αποδόσεων 2–3 φορές την ημέρα (ένα ξεχωριστό ελαφρύ workflow μόνο για αποδόσεις).
3. **Τραυματίες για την Ευρώπη** (ανακοινώσεις ομάδων ή EuroLeague API, αν το δίνει). Σήμερα οι απουσίες
   στα επερχόμενα μετρούν μόνο στο NBA.
4. **Λιγότερο CI.** Το μοντέλο παικτών και η σύγκριση όλων των αρχιτεκτονικών νευρωνικών μπορούν να τρέχουν
   μία φορά την εβδομάδα.
5. **Σταδιακά:** DuckDB αντί για CSV, ES modules στο site, tests για τους scrapers.
